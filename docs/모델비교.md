# 로컬 LLM 비교 — Qwen2.5 7B vs EXAONE 3.5 7.8B

- 테스트 날짜: 2026-11-15 · 환경: 개인 PC RTX 5060 8GB, Ollama 0.40.16, temperature 0
- 같은 코드, 같은 RAG 문서(bge-m3 임베딩), 같은 시연 시나리오 7개 (`tests/run_scenarios.py`)
- 원본 결과: `tests/scenario_result_qwen2.5.txt`, `tests/scenario_result_exaone3.5.txt`

## 결과 요약
| 항목 | qwen2.5:7b | exaone3.5:7.8b |
|---|---|---|
| Ollama 도구 호출(tools) 지원 | ✅ 기본 지원 | ❌ "does not support tools" → 프롬프트에 설명서를 넣고 `<tool_call>` 글자로 받는 방식으로 우회 |
| 알맞은 도구 선택 (7개 중) | 7 / 7 | 7 / 7 |
| 계산 인자 정확도 | ✅ 정확 | ⚠ "시급 9000원에 주 10시간이면?"에서 사용자가 말하지 않은 3.3% 공제(`tax_33=True`)를 넣고, 공제 후 금액을 "세전"이라고 잘못 말함 |
| 문서 근거 답변 | 정확, 짧음 | 정확, 더 자세함 (계산식·절차까지 정리) |
| 되묻기 · 개인정보 · 거래 거절 | ✅ | ✅ (거래는 은행 앱·창구로 안내하는 설명이 더 자연스러움) |
| 한국어 말투 | 간결, 가끔 어색 ("한 달 기본급" 오표현) | 자연스럽고 친절, 대신 답이 길다 |
| 응답 시간 (7개 합계) | 약 48초 | 약 93초 (첫 질문 모델 로딩 포함, 답이 길어 느림) |
| 모델 크기 | 4.7GB | 4.8GB |
| 비용 | 0원 (로컬) | 0원 (로컬) |

## 결론
- **기본 모델은 qwen2.5:7b 로 정했다.** 돈 계산에서는 말투보다 **인자를 정확하게 넣는 것**이 중요하다. EXAONE 은 사용자가 말하지 않은 조건(3.3% 공제)을 스스로 넣어 틀린 금액을 말했다.
- EXAONE 은 Ollama 에서 tools 기능을 지원하지 않아, 3장 11단계처럼 도구 설명서를 프롬프트에 넣는 방식이 필요했다 (`agent.py`의 `to_text_tool_messages`). 이 방식은 모델이 형식을 지키는지에 기대므로 덜 안정적이다.
- 설명형 질문(주휴수당 조건)의 답은 EXAONE 이 더 친절했다. 이후 개선 아이디어: 도구 선택은 Qwen, 최종 답 문장 다듬기는 EXAONE 으로 나누는 구성 (멀티 에이전트 가점 후보).
