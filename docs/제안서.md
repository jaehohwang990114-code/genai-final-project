# 제안서 — 알바머니 도우미

## LMS 제출용 (11주차)
- **팀 명단**: (이름1), (이름2)
- **주제 한 줄**: 아르바이트로 생활비를 버는 대학생이 알바비가 맞게 들어왔는지 확인하고, 남는 돈을 모을 적금 조건을 비교할 수 있게 돕는 에이전트
- **선택한 기술 2개**: RAG(노동·금융 안내 문서 검색) + 도구 호출(알바비·적금 계산, 상품 조건 비교)

## 1. 사용자와 문제
**가상 사용자: 대학교 2학년 김○○ (22세)**. 편의점 알바를 하루 4시간씩 주 5일 하며 자취 생활비를 번다.
- 시급, 주휴수당, 3.3% 공제가 어떻게 계산되는지 몰라서 **알바비가 맞게 들어왔는지 확인하지 못한다.**
- 매달 조금씩 남는 돈을 모으고 싶지만, 적금 금리 4%가 실제로 얼마인지, 우대조건이 뭔지 몰라 **은행 앱만 보다가 포기한다.**
- 사회적 가치: 청년 알바생의 임금체불·주휴수당 미지급은 계속 반복되는 문제다. 자기 권리를 숫자로 확인하는 첫걸음을 돕는다.

## 2. 하루 시나리오 (★ = 에이전트가 개입하는 순간)
| 시간 | 상황 | 에이전트 |
|---|---|---|
| 아침 | 월급날. 통장에 찍힌 알바비가 생각보다 적다. | ★ "시급 10,320원, 주 20시간, 3.3% 떼면 얼마야?" → `calc_alba_pay`로 계산, 주휴수당 포함 여부 비교 |
| 낮 | 쉬는 시간에 점장이 "주 14시간이라 주휴수당 없다"고 한다. | ★ "주휴수당 조건이 뭐야?" → `search_guide`로 근로기준법 안내 문서를 찾아 근거와 함께 설명, 1350 안내 |
| 저녁 | 이번 달 10만원이 남았다. 적금을 들까 고민한다. | ★ "10만원씩 12개월 넣으면?" → `compare_savings_products`로 조건 맞는 (가상) 상품과 만기 금액 비교, `search_guide`로 우대금리·중도해지 주의점 안내 |

## 3. 기술 선택 이유
- **RAG**: 주휴수당·세금·적금 규칙은 모델이 그럴듯하게 지어내기 쉬운 영역이다. 문서에서 찾은 내용만 답하게 해서 근거를 남긴다.
- **도구 호출**: 7B 로컬 모델은 곱셈·나눗셈을 자주 틀린다. 돈 계산은 파이썬 함수가 하고, 모델은 "어떤 계산이 필요한지"만 판단한다.
- 흐름: Gradio 입력 → Ollama(qwen2.5:7b)가 도구 선택 → RAG 검색 또는 계산 함수 실행 → 결과를 쉬운 말로 설명

## 4. 테스트 계획 (13주차 중간 점검: 정상 1 · 예외 2)
| 테스트 입력 | 기대 동작 |
|---|---|
| (정상) "시급 10320원에 하루 4시간 주 5일, 한 달에 얼마야?" | `calc_alba_pay(10320, 20)` 호출 → 세전 약 1,076,228원, 주휴수당 41,280원/주 |
| (예외) "한 달 알바비 얼마야?" | 시급·근무시간이 없으므로 도구를 부르지 않고 되묻는다 |
| (예외) "하늘은행 적금 해지 위약금 몇 %야?" | 문서에 숫자가 없으면 추측하지 않고 확인할 수 없다고 답한다 |

## 5. 보안·윤리·비용
- **개인정보 미수집**: 계좌번호·주민번호·카드번호·전화번호는 모델에 전달되기 전에 코드(`mask_pii`)로 가린다. 대화는 저장하지 않는다.
- **정보 안내 한정**: 법률·금융 판단을 하지 않는다. 특정 상품 가입을 권하지 않고 조건만 비교한다. 분쟁은 고용노동부 1350, 사기는 1332·112 안내.
- **최악의 오작동과 방지책**
  - 잘못된 계산으로 "체불이 아니다"라고 말함 → 계산은 테스트로 검증한 함수만 사용, 답에 계산식을 함께 보여 줌
  - 없는 상품 금리를 지어냄 → 상품 정보는 표·문서에서만, 시스템 프롬프트 + 검색 결과 없음 문장으로 이중 방지
  - 가상 상품을 실제 상품으로 오해 → 화면·도구 결과·답변에 '가상 상품' 표기
- **비용**: 학교 GPU 서버의 로컬 LLM만 사용하므로 API 비용 0원.
